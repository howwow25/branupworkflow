# 브랜업 대시보드

업무를 등록·조회·완료하는 사내 대시보드. 포털 타일 `watcher` →
`http://toffer.co.kr/branup/branup-watcher/`

용어는 [CONTEXT.md](./CONTEXT.md), 되돌리기 어려운 결정은
[docs/adr/](./docs/adr/) 에 있다.

## 구조

| | |
|---|---|
| 뼈대 | 표준 라이브러리만. `BaseHTTPRequestHandler` (`api_server.py`), 포트 8800 |
| DB | SQLite `data/db/branup.db` (`db.py`) |
| 화면 | `dashboard_html.py` 가 **정적 HTML 로 구워** 서빙. DB 가 바뀌면 다시 굽는다 |
| 반복 날짜·제목 | `recurrence.py` — DB 를 모르는 순수 함수 |

> **스키마를 고칠 때**: `db.py` 의 `SCHEMA_VERSION` 을 1 올려야 마이그레이션이
> 돕니다. 안 올리면 조용히 건너뜁니다 ([ADR 0003](./docs/adr/0003-sqlite-동시쓰기.md)).

## 배포

```powershell
cd <이 폴더>
.\update.ps1        # git pull → 화면 다시 굽기 → API 재시작 → 검증
```

## 반복 업무

업무를 만들 때 **🔁 반복**을 켜면 주·월·년 주기로 같은 업무가 생긴다. 횟수를
정하거나 **마감없음**으로 둘 수 있다.

미래 업무는 **최대 4개**만 미리 만든다. 하나가 끝나거나 날짜가 지나면 하나가
더 생긴다. 왜 그렇게 했는지는 [ADR 0001](./docs/adr/0001-반복업무.md).

- 위 **마감일**이 1회차다. 반복을 켤 때 비어 있으면 오늘로 채운다.
- 월말: 1월 31일에 걸면 2월은 28일로 당겨지고 **3월엔 다시 31일**이다.
- 방치했다 들어와도 지난 회차를 쏟아내지 않는다. 다만 **건너뛴 회차도 횟수를
  센다.**
- 지운 미래 회차는 되살아나지 않는다.
- 멈추려면 업무를 열고 **🔁 반복 중단**. 이미 만든 미래 업무를 지울지는
  그 자리에서 고른다.
- 주기 변경은 없다. 멈추고 새로 만드는 쪽이 범위가 분명하다.

**고칠 때와 지울 때는 범위를 묻는다** — `이 업무만` / `이 업무와 이후 모두`.
완료한 회차는 어느 쪽이든 바뀌지도 지워지지도 않는다.

| 고른 것 | 지울 때 일어나는 일 |
|---|---|
| 이 업무만 | 그 회차만 지우고, **창을 채우려고 다음 회차 하나가 새로 생긴다** |
| 이 업무와 이후 모두 | 이후 미완료 회차를 함께 지우고 **반복을 멈춘다** |

이후 모두를 지울 때 반복을 멈추지 않으면 보충이 곧바로 새 회차를 만들어,
지운 사람 눈에는 아무 일도 안 일어난 것처럼 보인다.

### 주기마다 이름 자동 변경

제목에 기간을 적어 두면(`[재무리뷰] 10월 3주`) 회차마다 그 부분만 바꿔 준다.
생성 폼에서 체크하거나, 이미 도는 업무를 열어 체크한다 — 켜는 순간 아직 오지
않은 회차의 이름이 맞춰진다. 자세한 이유는
[ADR 0002](./docs/adr/0002-제목-기간표시.md).

| 제목에 적은 것 | 다음 회차 |
|---|---|
| `[재무리뷰] 10월 3주` | `[재무리뷰] 10월 4주` → `11월 1주` |
| `2026년 12월 5주 보고` | `2027년 1월 1주 보고` |
| `월말 정산 10월` | `월말 정산 11월` |
| `2026년 정기감사` | `2027년 정기감사` |

- **주차는 `⌈일/7⌉`** 입니다 (= 그 달의 n번째 같은 요일). 19일 → 3주.
- 원래 없던 연도를 붙이지 않습니다.
- **기간 표시가 없는 제목에는 켤 수 없습니다.** 조용히 넘기면 켜진 줄 알고
  몇 주를 보냅니다. 체크하면 폼이 회차 4개의 이름을 미리 보여 줍니다.
